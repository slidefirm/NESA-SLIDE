# HTML 編輯模式：圈選 + 拖曳縮放 + 存檔/版本回朔

日期：2026-07-05
狀態：已與使用者對話確認方向，待寫實作計畫

## 背景

專案的 HTML 簡報渲染流程（`html-pattern-slide` skill）已經有共用元件
[artifacts/html-test/edit-mode.js](../../../artifacts/html-test/edit-mode.js)，
掛在播放器外殼上，目前支援：

- 編輯模式開關（E 鍵）
- 拖曳移動 `.el` 元素（滑鼠位移除以目前縮放比例，換算回 1920×1080 絕對 px）
- 點擊文字直接編輯（contenteditable）
- 「座標異動清單」：記錄每個元素的原始座標 → 新座標，附複製按鈕，供人工抄進
  theme 檔 `layout_overrides`
- 「匯出調整後 HTML」：把目前 DOM 存成新的靜態 HTML 檔案下載（純瀏覽器端）

使用者這次要求的「圈選元素、拖動位置、拉扯邊框動態放大縮小」，缺的是：

1. 明確的「選取」狀態（現在編輯模式一開，所有元素同時可拖，沒有『先選中一個才出現控制點』的概念）
2. 拉邊框縮放（完全沒有）
3. 「改動能不能被記錄、下次打開會不會重來」——現有機制只有「關掉分頁就消失」跟
   「手動匯出新檔」兩種，沒有「存回原始檔」或「版本回朔」

本次設計把這三塊都補上，範圍限定在擴充 `edit-mode.js` 這一個共用元件，
以及新增一支本地存檔用的小伺服器腳本，不改動個別簡報 HTML 檔案本身
（它們都是用 `<script src="edit-mode.js">` 引用同一份共用檔，改一次全部生效）。

## 目標

- 點擊選中一個元素 → 顯示 8 個控制點（四角 + 四邊）
- 拖角落控制點 → 等比縮放（寬高鎖定同一係數）；拖邊中點控制點 → 單方向縮放（只改寬或只改高）
- 縮放時字級跟著容器等比縮放（依實際改變的軸計算縮放係數）
- 異動記錄擴充成同時記 left/top/width/height/font-size
- 支援「存回原始 HTML 檔案」，存檔前自動備份成快照（版本回朔的資料來源）
- 支援瀏覽器 `localStorage` 草稿自動存檔，防止關分頁忘記存檔而遺失異動
- 沒有連上本地伺服器時（例如直接雙擊開檔），存檔/版本回朔功能靜默不可用，
  但既有的「匯出新檔」「異動清單」（純瀏覽器端）不受影響

## 非目標（刻意不做）

- 不做多選、不做群組縮放
- 不做「鎖定長寬比」開關——角落固定等比、邊線固定單方向，不提供切換
- 不處理巢狀子元素各自獨立縮放字級（目前 `.el` 多半是單一文字塊或圖片，沒有這個案例）
- 不做即時規則檢查（不擋使用者把元素拖出安全框、字級拖出角色範圍）——沿用
  `html-generation-rules.md` 規則 6 既有原則：生成當下是硬規則，編輯時只是參考線
- 存回原始 HTML 檔 ≠ 寫回七段式 YAML 或 theme 檔 `layout_overrides`——這條既有限制不變。
  若之後重新用 AI 生成同一個輸出路徑，手動存檔的調整會被蓋掉；要沉澱成規則，
  仍需人工透過異動清單抄進 theme 檔
- 版本備份不做自動清除或數量上限，理論上會一直累積——之後真的變成問題再處理
- 不做多人協作或鎖檔機制（同一檔案兩分頁同時編輯會互相覆蓋，先不處理）

## 設計

### 1. 選取模型

進入編輯模式後，點擊（mousedown+mouseup 無明顯位移）任一 `.el` 使其成為
「目前選取」，同時最多一個（不做多選）。選取後該元素外框變成實心高亮色
（跟其餘元素的淡虛線做出區隔）。點空白畫布區域或按 Escape 取消選取；
切換到另一個元素時，舊選取自動清除。

文字編輯（點兩下進入 contenteditable）與選取狀態分開處理，互不影響：
選取只決定「要不要顯示控制點」。

### 2. 控制點與縮放邏輯

- 8 個控制點：四角（NW/NE/SW/SE）+ 四邊中點（N/S/E/W）
- 控制點以 `position: fixed` 掛在 `document.body`（不是 `#stage` 內部子元素），
  用 `getBoundingClientRect()` 換算螢幕座標即時同步位置。原因：`#stage` 本身有
  `transform: scale()`，若控制點是 stage 內部子元素，畫面縮得越小控制點會跟著
  縮成米粒大小、難以點擊；掛在 body 上維持固定螢幕像素大小，不受縮放影響。
- 拖曳角落控制點：等比縮放，縮放係數以拖曳方向的位移計算，同步套用到寬跟高
- 拖曳邊中點控制點：單方向縮放，只改寬（E/W）或只改高（N/S）
- 寬高下限各 20px，防止拖到 0 或負值
- 換算方式跟現有拖曳一致：滑鼠位移先除以目前 `getScale()`，再套用到
  1920×1080 的絕對 px
- 控制點位置在選取變化、拖曳移動、拖曳縮放、`window resize` 時都要重新計算

### 3. 字級跟隨縮放

- 每個元素第一次被縮放時，記住當時的 computed font-size（原始字級）
- 縮放係數：
  - 角落控制點：寬高比例鎖定相等，取其中一個當縮放係數
  - 邊中點控制點：只有一個軸實際改變，縮放係數 = 該軸的新舊比例
- 新字級 = 原始字級 × 縮放係數，即時套用在該元素的 inline `font-size`
- 只套用在元素本身，不處理巢狀子元素

### 4. 異動記錄擴充

現有「座標異動清單」（`R` 鍵開啟面板）目前只記 left/top，擴充成同時記
width/height/font-size。格式範例：

```
title：left 96px→120px，top 96px→96px，width 800px→960px，
height 200px→240px，font-size 52px→62px
（Δx=24, Δy=0, Δw=160, Δh=40）
```

拖回/縮回原始數值（位置跟尺寸都要一致）才會從清單移除，避免假異動。
複製清單、匯出 HTML 功能不變。

### 5. 元素識別鍵（給存檔/草稿用）

`.el` 元素沒有唯一 id，只有 class（同一份 deck 內多張投影片會重複 class 名稱，
例如每頁都有 `.el.title`）。但每張 `.slide` 有穩定的 `id`（`s1`、`s2`...）。
用 `(slide.id, 該投影片內第幾個 .el)` 當識別鍵——只要不插入/刪除元素、
DOM 順序不變，這組鍵在單一頁面生命週期內以及跨 reload 都穩定可靠。

### 6. 存檔 API（本地小伺服器）

新增 `artifacts/html-test/dev_server.py`，取代目前 `.claude/launch.json` 裡
`html-test` 設定用的 `python -m http.server`，一樣能當靜態檔案伺服器
（同目錄、同 port 7392），純 Python 標準庫，不新增套件依賴。額外提供：

- `POST /__save`：body `{ "path": "deck.html", "html": "<!doctype...>" }`
  1. 驗證 `path` 解析後必須落在 `artifacts/html-test/` 目錄內，否則回 400
     （防止路徑穿越寫到目錄外的檔案）
  2. 若目標檔案已存在，先複製目前內容到
     `artifacts/html-test/.history/<檔名>/<ISO 時間戳記>.html`
  3. 用傳入的 `html` 覆寫目標檔案
  4. 回傳 `{ "ok": true, "snapshot": "<時間戳記>" }`
- `GET /__history?path=deck.html`：列出該檔案目前所有快照時間戳記，新到舊排序
- `POST /__revert`：body `{ "path": "deck.html", "snapshot": "<時間戳記>" }`
  1. 先把「還原前的目前狀態」也存一份快照（還原本身可以再復原，沒有真正回不去的操作）
  2. 把選定快照的內容複製回目標檔案
  3. 回傳 `{ "ok": true }`

### 7. 前端整合（`edit-mode.js`）

- 工具列新增兩顆按鈕：「儲存 (Ctrl+S)」「歷史版本」
- 「儲存」：把目前 DOM 清掉編輯用的暫時元素（outline、contenteditable 屬性、
  控制點覆蓋層、readout 標籤）後的 `outerHTML`，POST 到 `/__save`，
  `path` 取自 `location.pathname` 的檔名。成功後顯示簡短確認
  （例如「已儲存 12:34:56」），並清掉 localStorage 草稿
- 「歷史版本」：開啟面板，`GET /__history` 列出時間戳記 + 「還原」按鈕；
  點選後二次確認，`POST /__revert`，成功後 reload 頁面反映還原結果
- `localStorage` 草稿自動存檔：拖曳/縮放/改文字後 debounce 約 1.5 秒，
  把「哪張投影片、第幾個 `.el`、目前 left/top/width/height/font-size/文字」
  的精簡清單（用第 5 節的識別鍵）存進 `localStorage['edit-draft:' + location.pathname]`
- 頁面載入時若偵測到對應 key 的草稿，先跳出提示「發現未儲存的草稿，要恢復嗎？」，
  使用者選擇恢復或捨棄，不自動套用
- 若 `/__save`、`/__history` 的 fetch 失敗（沒有連上本地伺服器，例如直接雙擊開
  HTML 檔案），顯示「未偵測到本地伺服器」提示，不拋錯、不影響其他既有功能

### 8. `.claude/launch.json` 調整

`html-test` 設定的 `runtimeArgs` 從
`["-m", "http.server", "7392", "--directory", "artifacts/html-test"]`
改成指向 `dev_server.py`（保留 port 7392、保留靜態檔案服務行為）。

## 驗證計畫

1. 啟動 `html-test`（新的 `dev_server.py`），確認靜態檔案服務行為跟原本
   `http.server` 一致（既有的 `deck.html` 等測試頁能照常開啟、換頁、縮放）
2. 用 `preview_click` / `preview_eval` 驗證：
   - 點擊元素出現 8 個控制點，控制點螢幕像素大小不隨視窗縮放改變
   - 拖角落控制點：寬高等比變化，字級跟著縮放係數變化
   - 拖邊中點控制點：只有單一軸變化，字級跟著該軸係數變化
   - 縮放到最小值時不會變成 0 或負值
   - 點空白處 / Escape 會取消選取、隱藏控制點
3. 驗證異動清單（`R` 鍵）內容包含 width/height/font-size 且格式正確
4. 驗證存檔：點「儲存」後用 `preview_network` 確認 `POST /__save` 回傳 200，
   直接讀取磁碟上的檔案內容確認已覆寫，且 `.history/` 目錄下多了一筆快照
5. 驗證版本回朔：對同一檔案存檔兩次產生兩筆快照，用「歷史版本」面板還原到
   第一筆，確認檔案內容跟頁面顯示都回到第一筆的狀態
6. 驗證草稿：編輯後不按存檔、重新整理頁面，確認跳出「發現未儲存的草稿」提示，
   選恢復能正確套用回對應元素
7. 驗證無伺服器情境：直接用 `file://` 開啟同一份 HTML（不透過 dev_server.py），
   確認「儲存」「歷史版本」顯示未連上伺服器的提示，不報錯，且「匯出新檔」「異動清單」仍正常運作
